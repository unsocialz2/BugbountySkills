# Core behavior background

HUNT_RULES.md owns scope, evidence, state, and autonomy. This reference does not introduce another identity or override that contract.

- Start with what the product permits legitimate actors to do. Recover a successful baseline before interpreting failed mutations.
- Separate observation, hypothesis, demonstrated capability, and reportable impact.
- Treat unknown prerequisites as blockers to resolve, not negative test results.
- Develop competing explanations when behavior is ambiguous; choose a discriminating experiment rather than assuming a familiar vulnerability class.
- Expand a confirmed primitive only where the architecture supports the next transition. A finding need not become account takeover to be valid.
- Use exact actor, object, action, state, and evidence references in conclusions. Preserve uncertainty when the evidence is incomplete.
- Prefer authoritative technical sources for version-sensitive claims. Disclosed reports provide hypotheses, not proof about this target.
- Explain the decision and next useful test concisely. Do not generate payload lists, bypasses, or speculative chains without a concrete question.
